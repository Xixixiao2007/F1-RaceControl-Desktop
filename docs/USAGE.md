# 使用说明

## 一条命令启动

```bat
python tools\build.py --native --run -- --open --all-boards
```

- `--native` 顺便编译看板原生窗口（第一次要联网取 WebView2 包）
- `--run` 编译完直接启动
- `--` 之后是传给程序的参数

启动后控制台会打印：

```
F1-Race Control 桌面版 0.1.0
  界面目录 : ...\web
  数据源   : 官方公开流（实时）
  本机     : http://127.0.0.1:8720/
  局域网   : http://192.168.1.103:8720/   <- 手机 / iPad 用这个
  防火墙   : 未处理（加 --firewall 自动加规则；手机连不上多半是这里）
  窗口程序 : 原生 F1BoardWindow.exe
```

`Ctrl+C` 退出。

## 全部参数

| 参数 | 说明 |
| --- | --- |
| `--port N` | 监听端口，默认 `8720`；`0` 表示随便挑一个空闲端口 |
| `--web DIR` | 界面资源目录，默认自动找 `web/`（找不到就用 jar 里内置的） |
| `--open` | 启动时打开主界面窗口（**这是默认行为**；不要窗口用 `--no-window`） |
| `--board a,b,c` | 启动时就把指定看板拉成独立窗口（平时不用：界面上点「弹出」即可） |
| `--all-boards` | 启动时把全部 9 块看板都拉出来 |
| `--no-watchdog` | 窗口不监视服务器死活（调试用；默认服务器没了窗口会自己退） |
| `--list-boards` | 列出看板 id 后退出 |
| `--board-exe PATH` | 指定 `F1BoardWindow.exe` 路径（默认自动找） |
| `--firewall` | 自动加 Windows 防火墙入站规则（会弹一次 UAC） |
| `--firewall-check` | 只检查防火墙状态和端口监听，不改动、不提权 |
| `--replay FILE` | 用 `.rclog` 回放文件，不连网 |
| `--speed N` | 回放倍速，默认 `60` |
| `--delay SEC` | **显示延时**（秒，0 = 关闭）：整个界面滞后 SEC 秒，用来对齐有延迟的电视/直播画面 |
| `--main-size WxH` | 主窗口尺寸，默认 `1600x900` |
| `--board-size WxH` | 看板窗口尺寸，默认 `620x420` |
| `--no-window` | 只起服务器，不开窗口 |
| `-h`, `--help` | 帮助 |

## 看板窗口

### 显示延时：把画面滞后几秒，对齐电视/直播

电视和网络直播比官方计时源**晚**几秒到几十秒，不处理的话 App 会"剧透"电视上
还没发生的画面（比如你已经看到"黄旗"了，电视上还在正常跑）。设一个延时就对上了：

- **网页上随时调**：主界面右上角有「延时 关」和一对 **−/＋**（各 5 秒），
  点一下立刻生效，**不用重启**；手机版那一行放不下两个按钮，点「调」直接输数字；
- **启动参数**：`--delay 30`（秒，0 = 关闭，上限 600）；
- 调好的值会记住，下次开机还是它（存在 `%LOCALAPPDATA%\F1-RaceControl-Desktop\delay.txt`）。

三条要知道的：

1. **整个界面一起滞后**（成绩、圈速、圆环、旗语、通报、以及红旗那类提醒），
   所以各面板之间不会打架；
2. **接上时先显示当前状态**，之后的更新才开始滞后 —— 不会一启动就黑屏 30 秒；
3. **调大之后画面会先停住**，停够新设置的秒数再继续（因为它要开始显示"N 秒之前"）；
   **调小立即生效**，压着的更新会马上放出来。不丢数据。

回放模式下没有延时（回放本身就是一条时间轴），点了网页上的按钮会如实告诉你
"回放模式没有显示延时"，不会假装生效、也不会把你直播模式存的值改掉。

每块看板都是一个**独立的原生窗口**：可以随便拖动、拉伸缩放，任务栏里各自有图标，
最小化/关闭互不影响，就像微信/QQ 的窗口一样。

### 在界面上随手弹出 / 收回

不用记命令行 —— 主界面上**每块面板的标题栏右侧**都有一个「弹出 / 收回」按钮，
点标题栏整条也一样（内容区不受影响，通报列表照样能滚动、能选文字）：

- 点「弹出」→ 按钮变成蓝色的「收回」
- 点「收回」→ 关掉那块小窗
- 直接用窗口右上角的 X 关掉也可以，按钮会在 3 秒内自己变回「弹出」

**点「弹出」得到的是小窗还是标签页，看你正在用哪个界面**（服务器自己判断，前端不猜）：

| 你在哪 | 结果 | 服务器返回 |
| --- | --- | --- |
| 桌面客户端（原生窗口） | 独立原生小窗，可移动可缩放 | `mode:"native"` |
| 浏览器里（本机或手机） | 新标签页，页面就是那块看板 | `mode:"tab"` + `url` |

浏览器里**不会**弹原生窗口 —— 那是"网页版"，弹出也应该是网页。判断靠原生窗口
在 UA 上盖的标记（`F1RaceControlShell/1`）；来源地址只决定**能不能**开窗口。

**启动时默认只开主界面**，看板窗口都是你自己点出来的 —— 需要哪块点哪块，
不用一上来铺满屏幕。弹出去的小窗想一次全关：主界面右上角状态栏上有
**「收回全部 (N)」**（`N` 是当前弹着几块），点一下就全部收回，主界面自己留着。
小窗自己的标题栏里也有同一个按钮，所以在任何一个小窗里都能一键收干净。

这个按钮**只在桌面客户端里显示**（`canNative` 为真时）：窗口在服务器那台电脑上，
浏览器和手机上都动不了它们，摆这个按钮是骗人；真去点也只会拿到一句
「网页版里收不了本机窗口，请在桌面客户端里点」。

手机上如果浏览器拦了新标签页，允许一次就行。

> 只有**本机**能触发开原生窗口。局域网里的其它设备发这个请求只会拿到一个新标签页
> 的地址 —— 否则同一网段任何人都能让你的电脑弹窗。

服务器启动后会打一行说明第一个页面是从哪来的，排查"点了没反应"时先看它：

```
[web] 第一个页面连接来自：本机 · 我们的窗口     <- 原生客户端
[web] 第一个页面连接来自：本机 · 浏览器         <- 本机浏览器打开
[web] 第一个页面连接来自：局域网设备            <- 手机 / 平板
```

命令行当然也能直接拉：

```bat
--board tyres,timing,ring        :: 启动时就只要这三块
--all-boards                     :: 启动时全部铺出来
```

窗口位置和大小**会按看板 id 记住**，下次打开回到原位 —— 摆一次就够了。
**摆过的窗口**再打开时就用记住的位置；只有从没摆过的（第一次开）才按 3 列网格铺开，
免得一上来几个窗口全叠在左上角。想手动指定位置，命令行给的
`--x/--y/--width/--height` 优先级更高，会盖掉记忆。

（位置不用等关窗：每次移动/缩放**停手约 1 秒**后就写下了 —— 从网页上点「收回」
是强杀、不走窗口自己的关闭流程，所以只能靠这个时机记住位置。）

### 服务器退出后，小窗会自己关

每个窗口每 3 秒问一次服务器的 `/api/health`，连续 4 次不通（约 12 秒）就自己关掉。
这样关掉那个 cmd 控制台窗口之后，桌面上不会留下一堆显示"连接断了"的空壳。

**还没成功探到过一次**的窗口用更耐心的门槛：10 次（约 30 秒）。
这条兜底是必要的 —— 服务器要是在窗口刚起步就死了（第一次探测还没成功过），
按 4 次那套计数**永远不会开始**，窗口就会一直留着。正常启动几秒内就能探到，
30 秒足够；真是早早死了，最多多留 30 秒也会自己走掉。

> 为什么不是"服务器退出时去关窗口"：实测在 Windows 上，**关掉控制台窗口**时
> JVM 的 shutdown hook 根本不执行（按 `Ctrl+C` 才会执行）。所以这件事必须由
> 窗口这一侧发现，不能指望服务器在退出前通知谁。顺带这也覆盖了任务管理器
> 结束进程、服务器崩溃等情况。
> 依据与复现脚本：`tools/probe_hook.py`、`tools/test_watchdog.py`、
> `tools/test_watchdog_early.py`（后者专门盯上面那条"没见过成功"的兜底）。

调试时不想让它自动退：`--no-watchdog`。

快捷键：`F11` 全屏，`Esc` 退出全屏。

### 八块看板建议摆法

```
python tools\build.py --run -- --board flags,ring,track,tyres,timing,weather,fastest,session
```

默认按 3 列网格铺开（每块 620×420），起点在屏幕左上角。

**窗口会不会互相压着？** 会，而且这在单屏 1080p 上无法避免：主界面
1600×900 加上几块看板，面积本来就超过一屏。所以实际用法是二选一 ——

- 只想看总览：只开主界面（`--open`）
- 想让某几块面板一直显示：把那几块拉出来（`--board tyres,timing`），
  主界面留在后面当底图，需要时点任务栏调出来

先摆一次位置就好：**每个窗口的位置和大小都会按看板 id 记住**
（存在 `%LOCALAPPDATA%\F1-RaceControl-Desktop\windows\`），下次打开回到原位。
想重新排，删掉那个目录里的对应 json 即可。

## 手机上用（含 iPhone）

1. 电脑上启动时带上 `--firewall`（第一次）：
   ```bat
   python tools\build.py --run -- --firewall --open
   ```
   会弹一次 UAC 问你要不要允许，点"是"。
2. 手机连**同一个 Wi-Fi**，浏览器打开控制台打印的那个局域网地址，例如
   `http://192.168.1.103:8720/`
3. iPhone 上可以「共享 → 添加到主屏幕」，之后像 App 一样从桌面图标打开。

界面是自适应的，手机上是**和安卓同款**的排布（不是把 6 块都堆起来），尺寸也对齐安卓：

| 朝向 | 显示 |
| --- | --- |
| 竖屏 | 旗语栏（42px = 安卓 `dp(42)`）+ 赛事通报（**没有**圆环、没有右侧那 6 块） |
| 横屏 | 旗语栏 + [ 通报 \| 一屏面板 \| 窄框图标条 ]，左边和面板**各占一半**（安卓两边都是 `weight=1`），窄条 38px（`dp(38)`） |

横屏右栏一次只显示一屏，默认「赛道图（圆环）」，图标和安卓 `RightPanelView`
一致：`◎ 赛道图` `◍ 轮胎` `≡ 成绩` `☂ 天气` `⏱ 最快圈` `ⓘ 环节`。

手机版**没有顶部大标题行** —— 安卓的布局里也没有，状态行是塞在左栏顶上的
（`buildStatusRow`），所以连接状态和按钮都放在那一行薄状态行里：

- **单独打开**：把当前这一屏开成新标签页（手机上弹不出原生窗口）；
- **全屏**：藏起浏览器地址栏，多出一截高度。iPhone 的 Safari 不支持对网页全屏
  （只给 video），点它会提示「分享 → 添加到主屏幕」——那条路是真能去掉地址栏的。

判据是屏幕**短边 ≤ 560px** —— 只按宽度判的话，横屏手机（844×390）会被当成桌面，
又铺回 6 块。平板和电脑窗口不受影响。

### 手机打不开时

先跑一次自查（**不提权、不改任何设置**）：

```bat
启动.cmd --firewall-check
```

它会报三件事，对应三种完全不同的修法：

```
  防火墙检查: 规则名 F1-RaceControl-Desktop 不存在      ← 防火墙没放行
             端口 8720 未被覆盖
             本机监听 正常                              ← 服务器这边是好的
```

| 看到什么 | 说明 | 怎么办 |
| --- | --- | --- |
| 本机监听 ★ 没在监听 | 服务器/端口的问题，跟防火墙无关 | 换端口，或看服务器是不是启动失败 |
| 规则不存在 / 端口未被覆盖 | 防火墙没放行 | 加 `--firewall`，或用下面那条 netsh |
| 两项都正常手机还是打不开 | 问题在网络，不在本机 | 往下看第 1、4、5 条 |

按这个顺序查（**本机能打开、手机打不开，九成是第 2 条**）：

1. 手机和电脑是不是同一个网段（电脑上 `ipconfig` 看 IPv4 地址）
2. 防火墙有没有放行：管理员 PowerShell 里跑
   ```bat
   netsh advfirewall firewall show rule name=F1-RaceControl-Desktop
   ```
   没有就加：
   ```bat
   netsh advfirewall firewall add rule name=F1-RaceControl-Desktop dir=in action=allow protocol=TCP localport=8720 profile=private,domain
   ```
3. 电脑上先自己验证服务器活着：
   ```
   http://127.0.0.1:8720/api/health
   ```
   应该返回 `{"ok":true,...}`
4. 路由器有没有开「AP 隔离 / 客户端隔离」—— 开了的话同一 Wi-Fi 下的设备也互相不通
5. 公司/学校的网络可能禁止设备互访

## 没有比赛的时候

```bat
python tools\build.py --run -- --replay ..\F1-RaceControl\tools\mock_data\bahrain2026_race.rclog --speed 200 --open --all-boards
```

`.rclog` 也能直接用安卓版的数据，回放会按原速的 N 倍把整场比赛"重演"一遍，
用来调布局、试看板摆放、验证手机能不能连，都不需要等比赛。

默认只放一遍，放完停在最后一帧。

## 故障排查

**窗口开不出来 / 任务栏图标是浏览器**
说明没找到 `F1BoardWindow.exe`，程序会明确打印「降级用 Edge/Chrome」。装 .NET 运行时后：

```bat
python tools\build_native.py
```

**窗口里显示「WebView2 初始化失败」**
缺 WebView2 运行时。Win11 和较新的 Win10 自带；没有的话装一个：
<https://developer.microsoft.com/microsoft-edge/webview2/>

**页面一片空白，但接口正常**
现在页面会把脚本错误直接显示在底部红条上。没有红条却空白，就在地址后面加 `?once=1`
看是不是长连接的问题。

**端口被占用**
换一个：`--port 8800`。用 `--port 0` 让系统随便挑也行，实际端口会在启动信息里打印。

**控制台里的中文变成问号/乱码**
0.1.8 已修，用新版的 `启动.cmd` 就正常。原因值得记一笔：启动脚本里的 `chcp 65001`
会把控制台切到 UTF-8，而 Java 8 拿到这个代码页后**自己编错了**（它把
`sun.stdout.encoding` 报成 `cp65001`，实际却用平台默认的 GBK 去编码），于是写出的
字节和控制台的对不上 —— 同一个窗口里 `cmd.exe` 自己 echo 的中文倒是好的。
自己手动 `java -jar` 时也修好了；万一在别的地方还遇到，加上这个参数就行：

```bat
java -Dsun.stdout.encoding=UTF-8 -Dsun.stderr.encoding=UTF-8 -jar F1-RaceControl-Desktop.jar --open
```

**任务管理器里看到两个 `java.exe`**
正常，不是双开。用 PATH 里的 `java`（Oracle JRE 装的 `javapath` 转发器）启动时，
它本身就是个小程序（约 12MB、1 个线程、不占端口），真正跑起来的是它派生出来的
`...\jre1.8.0_481\bin\java.exe`。看谁在干活认线程数和端口就行。
用 `启动.cmd` 直接指定完整 java 路径启动时不会多这一层。

**圆环看起来还是不正 / 糊**
画布上带了一个 `data-fit="宽x高"` 属性，记录它当时量到的盒子尺寸。
在窗口里按 `F12` 打开开发者工具，选中 `<canvas class="ring">` 看一眼：
- `data-fit` 里两个数不相等 → 是布局问题（盒子还没量到），报一下
- 两个数相等，但 `width`（像素）不等于 `style.width`（CSS px）且不是缩放倍数关系 → 是缩放问题

正常情况下 `width` = `style.width` × 系统缩放倍数（125% 缩放就是 1.25 倍），
这是刻意做的：高分屏上按物理像素绘制，字和线才不糊。

**想看原始数据**
`http://127.0.0.1:8720/api/full` 是所有合并后的原始流（很大）；
`/api/state` 是界面实际用的那一份派生状态。

## 界面上的每一块

| 面板 | 内容 |
| --- | --- |
| 顶部旗语栏 | 按区段显示黄旗/双黄旗/安全车等，无旗语时显示整条绿（全赛道畅通） |
| 通报横幅 | 最新一条赛事通报，有中文用中文，没有就用英文原文 |
| 赛道图 | 环形显示各区段状态，圆心是当前总结（全赛道旗语显示在这儿）；角度由安卓那份 `F1Layout` 计算 |
| 赛道状态 | 当前旗语级别、涉及区段、TrackStatus 原始值 |
| 轮胎 / 进站 | 3 列 × 8 行共 24 格，按赛道位置排，显示配方、胎龄、进站次数 |
| 成绩榜 | 名次、车手、差距、间隔、配方、圈数、进站 |
| 天气 | 气温、赛道温、天气描述 |
| 个人最快圈 | 按最快圈排序，车手名前面带**车队颜色**（和成绩榜同款） |
| 环节 | 大奖赛、赛道、环节、状态、剩余时间、圈数、前三名 |
| 赛事通报 | 最近 60 条，每条**两行**：译文 + 英文原文（和安卓一样）；悬停看 F1 官方 UTC 时间戳 |
